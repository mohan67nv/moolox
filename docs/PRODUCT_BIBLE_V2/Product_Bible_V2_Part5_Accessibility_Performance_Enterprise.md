# PART 11 — ACCESSIBILITY

## 11.1 Platform Accessibility (Our Own Interface)

### Keyboard Navigation
| Context | Keys | Action |
|:---|:---|:---|
| **Global** | `Tab` / `Shift+Tab` | Move focus forward/backward through interactive elements |
| **Global** | `Escape` | Close modal/panel/dropdown, deselect element |
| **Global** | `Cmd+K` | Open command palette |
| **Global** | `Cmd+J` | Toggle AI Studio |
| **Canvas** | `Tab` | Select next sibling element in DOM tree |
| **Canvas** | `Enter` | Enter selected element (select first child) |
| **Canvas** | `Escape` | Exit current element (select parent) |
| **Canvas** | `Arrow keys` | Nudge selected element position (1px, +Shift = 10px) |
| **Canvas** | `Space+Drag` | Pan canvas |
| **Canvas** | `Cmd+Scroll` | Zoom canvas |
| **Canvas** | `Delete/Backspace` | Delete selected element |
| **Canvas** | `Cmd+D` | Duplicate selected element |
| **Canvas** | `Cmd+C/V` | Copy/Paste element |
| **Code Panel** | Standard VS Code bindings | Full code editing keyboard support |

### Focus Management
| Rule | Implementation |
|:---|:---|
| Focus indicators always visible | 2px ring using `accent.primary`, 2px offset. Never hidden by CSS. |
| Focus trap in modals | Tab cycles within modal. Focus returns to trigger on close. |
| Skip links | "Skip to canvas" and "Skip to main content" links visible on Tab from page top. |
| Focus restoration | After any panel close, modal dismiss, or overlay remove — focus returns to the element that triggered it. |

### Screen Reader Support
| Feature | Implementation |
|:---|:---|
| Canvas elements | Each canvas element announced with: role, name, position in parent ("Button, 'Get Started', 2 of 4 in HeroSection") |
| AI generation progress | `aria-live="polite"` region announces: "Generating site structure... Generating hero section... Generation complete. 5 pages created." |
| Property changes | When user modifies a property via slider/input, change is announced: "Font size changed to 24 pixels" |
| Error announcements | `aria-live="assertive"` for errors: "Error: Color contrast ratio is 3.2:1. Minimum required is 4.5:1." |
| Canvas zoom | "Canvas zoom level: 75 percent" announced on change |

### Color & Contrast
| Standard | Requirement |
|:---|:---|
| Text contrast (normal) | Minimum 4.5:1 against background (WCAG AA) |
| Text contrast (large) | Minimum 3:1 for text 18px+ or 14px+ bold |
| UI component contrast | Minimum 3:1 for interactive element boundaries against adjacent colors |
| Non-text contrast | Minimum 3:1 for icons and graphical elements |
| Focus indicator contrast | Minimum 3:1 against adjacent colors |

### Reduced Motion
| When `prefers-reduced-motion: reduce` | Action |
|:---|:---|
| All `motion.*` token durations | Collapse to 0ms (instant transitions) |
| Parallax effects | Disabled |
| AI streaming text animation | Text appears instantly (no character-by-character) |
| Canvas drag animations | Snap without spring/bounce |
| Loading skeleton shimmer | Replace with static opacity pulse |
| Page transitions | Cross-fade only (no slide/scale) |

### Color Blindness
| Type | Accommodation |
|:---|:---|
| **Protanopia / Deuteranopia** | Success/error states use icons (✓/✗) in addition to green/red color. Never rely on color alone. |
| **All types** | Interactive states (hover, active, focus) indicated by border/shadow changes, not just color shifts. |
| **Token system** | Semantic colors (`success`, `warning`, `error`) always paired with icons and/or text labels. |

### Internationalization & RTL
| Feature | Implementation |
|:---|:---|
| **RTL layout** | CSS logical properties throughout (`margin-inline-start` not `margin-left`). Sidebar flips to right. Text alignment flips. |
| **RTL in generated code** | When user selects RTL locale, AI generates HTML with `dir="rtl"` and CSS with logical properties. |
| **Unicode support** | Full UTF-8 support in all text inputs, AI prompts, and generated content. |
| **Locale-aware formatting** | Numbers, dates, and currencies formatted per locale in generated code. |
| **Translation-ready** | All platform UI strings externalized to i18n files. Community translation program for platform UI. |
| **Phase** | RTL support: P2 (v2.0). Basic i18n: P1 (v1.0). |

## 11.2 Generated Code Accessibility

Every site generated by the AI MUST pass these automated checks before publish:

| Check | Rule | Auto-Fix Behavior |
|:---|:---|:---|
| **Heading hierarchy** | No skipped heading levels (H1→H3 without H2). Single H1 per page. | AI restructures heading levels. |
| **Image alt text** | All `<img>` have descriptive `alt`. Decorative images use `alt=""`. | AI generates alt text from image analysis. |
| **Link text** | No "click here" or "read more" links. All links have descriptive text. | AI rewrites link text based on destination context. |
| **Form labels** | All inputs have associated `<label>` elements. | AI adds labels. |
| **Color contrast** | All text meets 4.5:1 (AA). | AI adjusts text or background color using nearest token value that passes. |
| **Button labels** | Icon-only buttons have `aria-label`. | AI generates descriptive label. |
| **Language attribute** | `<html lang="en">` (or appropriate locale) present. | Auto-added. |
| **Viewport meta** | `<meta name="viewport" content="width=device-width, initial-scale=1">` | Auto-added. |
| **Focus order** | Tab order follows visual reading order. | AI restructures DOM order if mismatch detected. |
| **ARIA landmarks** | `<main>`, `<nav>`, `<header>`, `<footer>` present. | AI wraps content in semantic landmarks. |

# PART 12 — PERFORMANCE

## 12.1 Platform Performance Targets

| Metric | Target | Measurement Method |
|:---|:---|:---|
| **First Contentful Paint (FCP)** | < 1.2s | Lighthouse CI on workspace load |
| **Time to Interactive (TTI)** | < 2.5s | WebContainer fully hydrated |
| **Canvas Frame Rate** | 60fps sustained | Performance monitor during drag operations |
| **AST Operation Latency** | < 5ms | WASM benchmark: parse → transform → serialize |
| **AI First Token** | < 500ms | Time from prompt submit to first streamed character |
| **Deployment Build** | < 5s | Time from "Publish" click to live URL |

## 12.2 Generated Site Performance Targets

| Metric | Target | Enforcement |
|:---|:---|:---|
| **Lighthouse Performance** | 95+ | Automated pre-publish audit. Block publish if <90. |
| **Lighthouse Accessibility** | 95+ | Automated pre-publish audit. Block publish if <85. |
| **Largest Contentful Paint** | < 2.5s | Image optimization, critical CSS inlining |
| **First Input Delay** | < 100ms | Minimal JS, hydration optimization |
| **Cumulative Layout Shift** | < 0.1 | Explicit width/height on images, font-display: swap |
| **Total Bundle Size** | < 150KB gzipped | Tree-shaking, code splitting, dynamic imports |

## 12.3 Performance Architecture

| Strategy | Implementation |
|:---|:---|
| **Streaming AI Responses** | Server-Sent Events (SSE) for AI generation. DOM updates rendered incrementally as tokens stream. No waiting for full response. |
| **Partial Canvas Rendering** | Only render visible viewport + 1 screen buffer. Elements outside viewport use placeholder rectangles. |
| **WASM AST Operations** | Rust-compiled AST parser runs in Web Worker. Main thread never blocked by code transforms. |
| **Image Optimization Pipeline** | All images auto-converted to WebP + AVIF. Responsive srcset with 5 breakpoint widths. Lazy loading with blur placeholder. |
| **CSS Critical Path** | Above-the-fold CSS inlined in `<head>`. Remaining CSS loaded async. Unused CSS purged at build time. |
| **Edge Caching** | Generated sites served from Cloudflare edge (200+ PoPs). HTML cached at edge with 1-hour TTL. Assets cached with immutable headers (1 year). |
| **Service Worker** | Platform workspace uses service worker for offline capability. Shell cached. API requests cached with stale-while-revalidate. |
| **Code Splitting** | Each page dynamically imported. Shared components in common chunk. Route-based splitting matches Next.js App Router behavior. |
| **Font Optimization** | Google Fonts or custom fonts served via `next/font` with `font-display: swap` and preload. Subsetting for non-Latin character sets. |

# PART 13 — COLLABORATION

## 13.1 Real-Time Presence
| Feature | Specification |
|:---|:---|
| **Cursors** | Colored cursors showing each active user's position on canvas. Name label on hover. |
| **Selection Highlight** | When another user selects an element, it shows a colored border with their avatar. |
| **Technology** | WebSocket (Cloudflare Durable Objects for room management). CRDT (Yjs) for conflict-free state synchronization. |
| **Latency Target** | < 50ms for cursor/selection updates between users. |

## 13.2 Comments & Review
| Feature | Specification |
|:---|:---|
| **Element-Pinned Comments** | Click any element + `Cmd+M` → comment pinned to that DOM element. Persists even if element moves. |
| **Thread Model** | Each comment starts a thread. Others can reply. Threads are resolvable. Resolved threads hidden by default. |
| **Mentions** | @username mentions trigger notifications. @team mentions notify all team members. |
| **Review Workflow** | Assignable review requests. Reviewer sees visual diff + comment threads. Actions: Approve / Request Changes / Comment. |
| **Status** | Project pages can be: Draft → In Review → Approved → Published. Status visible in page tree. |

## 13.3 Approval Gates
| Feature | Specification |
|:---|:---|
| **Staging Approval** | Any editor can deploy to staging. |
| **Production Approval** | Requires explicit approval from Admin or Owner role. |
| **Design Token Changes** | Changes to global design tokens require Admin approval (configurable per workspace). |
| **Audit Trail** | Every approval/rejection logged with timestamp, user, and optional comment. |

## 13.4 Version History
| Feature | Specification |
|:---|:---|
| **Auto-Save** | Every 30 seconds of inactivity or on explicit Cmd+S. |
| **Named Checkpoints** | Manual: User creates named checkpoint ("Pre-redesign backup"). Automatic: AI edits create named checkpoints. |
| **Visual Timeline** | Scrollable timeline with thumbnail previews at each checkpoint. |
| **Diff View** | Side-by-side visual comparison (screenshot overlay) + code diff (unified format). |
| **Branching** | Create branch from any checkpoint. Merge branches with visual conflict resolution. |
